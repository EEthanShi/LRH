## Conventions

- `orig_copy/` holds pristine copies of the OpenLLaMA-axis originals (`analysis/s12_layermax_openllama/early/`); each sha256 equals plan §3 and `S0B_CODE_MANIFEST.json` (`b2b55362…`), checked before copying.
- `X.diff` next to each copy is `diff -u orig_copy/<original> X`, generated on ds2213.
- Changed lines of the lightly edited copies (`lm_core.py`, `precompute.py`, `run_layermax.py`, `validate.py`, `vl7_prop5.py`, `write_hashes.py`) carry the marker `PYT-AXIS`. The rewritten copies (`aggregate_pyt.py`, `report_pyt.py`, `vl4_known_pyt.py`, `vl5_e_vs_i.py`) say in their header which functions are kept; new functions and blocks carry `PYT-AXIS` on their def line or first line, not on every line. The `.diff` lists every change.
- Output root `results/S1_2_layermax_pythia/early/` (`lm_core.RES`); E single-model cache `early/cache/`; shared clip cache `results/S1_2_layermax_pythia/cache/clip_thresholds.json`.
- **Gate (plan §4 F1(a)).** Every script calls `lm_core.gate(<script>)` first. Outside the S0b test mode it exits 3, having written nothing, unless (i) STATUS.md has a milestone line `<UTC>Z [pyt-axis-predict] Part B FROZEN` whose text contains the current sha256 of both `PARTB_PREDICTIONS_PYT.md` and `partB_features_pyt.json`, (ii) the E output root is `results/S1_2_layermax_pythia/early`, and (iii) the shared axis guard `analysis/s12_layermax_pythia/guard.py` exists, imports, and its `require_partb_frozen(<E root>)` passes. A missing or failing shared guard refuses (fail closed). `precompute.py` is gated too (the OpenLLaMA copy was not): its outputs lie in guarded directories that may not exist at the Part B freeze, and S6 follows S5, so no order of the plan changes.
- **S0b test mode.** `PYT_S0B_TEST=1` (the variable of the extraction side and of the shared guard) is accepted only while STATUS.md has no `[pyt-axis-<role>] CODE FROZEN` milestone line (else exit 3). Every output root then moves under `analysis/s12_layermax_pythia/s0b_scratch/E/` (`PYT_E_TEST_ROOT`), the 7 slugs become `synth__pyt-<size>` with stacks named by `PYT_E_TEST_STANDINS`, `PYT_E_TEST_PARTB` may point to a stand-in Part B under `s0b_scratch/`, and `PYT_E_TEST_DEVICE=cpu` runs the pair kernel on the CPU. The shared guard is called in test mode as well.

E was conformed to the spec version `73cccb6c…` (~01:35Z); the later version `2d5332eb…` (01:40Z) only adds §14 (records read by `s0b_freeze.py`), which E now provides (`s0b_dryruns_E.json`, the V-P8/V-P9 records and the test log of `tests/run_e_tests.py`). E read these four shared files and `f1d_outroots.py` (its interface to `lm_core`), not the I or R code and not `partb_pyt.py` or `forecast_pyt.py`. If the contract changes before the freeze, E must be re-checked against it.

## Plan items not implementable literally (reported)

1. **Per-ViT sign rule (plan §8).** "If c_α is non-decreasing in size over all 7 sizes for a ViT, ρ_v(score) ≤ ρ_v(raw)" is false under censoring: two sizes whose raw order is discordant can both be censored to 0, which turns a discordance into a tie and raises Spearman's ρ (example with 3 sizes: raw (0.30, 0.20, 0.50), thresholds (0.35, 0.35, 0.40), s_cal (0, 0, 0.167): ρ rises from 0.5 to 0.866). E follows the spec's resolution: ViTs with a censoring tie are excluded and counted (`signvit|…|nexcl_tie`), never treated as errors; the same exclusion applies to the D3 check.
2. **"Marker PYT-AXIS on changed lines"** for the rewritten files: block-level markers plus the full `.diff` (as on the OpenLLaMA axis).
3. **Interrupted S7** needs a restart that keeps both outputs; the inherited resume logic was replaced (see `run_layermax.py`).
4. **V-P9 "end to end through E, I, R and forecast_pyt.py with 0 mismatches"**: E's part runs end to end on the stand-in (all 8445 required keys); the joint E/I/R/forecast comparison needs the other roles' outputs and the shared stand-in Part B (`partb_pyt.py --standin vp9`), which did not exist when E was tested.
5. **GPU checks.** V-P1–V-P4 were smoke-tested on the CPU device only (the GPU is reserved; GPU-ORDER rule). The GPU behaviour (bitwise V-P4, GPU timings) is untested.
